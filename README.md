## Purpose

This repository records selected, attributable **Proof of Work** from the ongoing work of the DGCP™ System Architect. Its purpose is to make approved, publicly presentable work outputs and development milestones discoverable without reproducing the original Real-Work Data archive, protected proof chains, operational logs, or confidential institutional material.

**Proof of Work here means documented work and attributable public outputs.** It is not a blanket certification, independent audit, on-chain proof, or assertion that a GitHub contribution count proves individual events.

The System Architect's real work and daily recording **continue in their existing repositories and systems**. This repository is an additional public presentation and reference surface. It does not replace, rename, migrate, reset, or rewrite any existing archive or daily sequence.

## What Belongs Here

Only approved public-facing work records, for example:

- A completed and publicly accessible document or publication with an identifiable source.
- A released website or other system milestone with an observable result and a reference that can actually be opened by the intended audience.
- A factual development record that distinguishes work performed, observed results, unresolved limitations, and release status.
- A public correction or follow-up that links forward to the earlier statement without rewriting its history.

Each public entry should be compact, evidence-bounded, dated, attributable and clear about its verification limits.

## What Does Not Belong Here

No automatic copying or publishing of Raw Data, Data Units, original Proof files, daily ledgers, OTS records, CIDs, device metadata, private research, internal system diagrams, credentials, confidential methods, unpublished IP or private repository links presented as though accessible.

Repository metadata, contribution graphs and commit counts are **activity indicators**, not substitutes for original evidence or independent validation. Do not create daily records here merely to duplicate commits or inflate a metric.

## Daily Continuity

The established **daily work, recording, proof and commit workflow continues in its original authorized locations**, with its existing identifiers, sequences, provenance, and rights. No new numbering is assigned here to historical events.

When a day's **public-facing result is approved for inclusion**, add a dated record under:

`work/YYYY/MM/YYYY-MM-DD.md`

Suggested minimum entry fields:

- Date of work and, if different, date of public release
- Work title and concise description of the completed output
- Public source URL or other authorized reference
- Verified outcome and clearly labeled limitations
- Correction or supersession link, when applicable
- `License: DGCP | MMFARM-POL-2025`

A day with no approved public record remains represented in the original workflow. It must **not** be manufactured, backfilled, or reported as missing proof in this presentation repository.

## Integrity Rules

1. Source observations remain where they were originally recorded.
2. Preserve original identifiers, timestamps, sequence and attribution; never fabricate a cross-repository mapping.
3. Publish only what the System Architect authorizes for the public.
4. Keep older published records traceable. Add dated correction/supersession records instead of silently changing historical meaning.
5. Distinguish work produced by the System Architect from assistant-generated drafts, and do not assign authorship or human proof to automated output.
6. Identify whether a reference demonstrates a document, a deployment, a technical integrity property or an independently reviewed outcome; do not conflate them.
